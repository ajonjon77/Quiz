📘 PostgreSQL 複習指南

基於 PostgreSQL Essentials v16 教材整理

一、PostgreSQL 架構（Architecture）

程序架構

  • PostgreSQL 使用 Process（程序） 而非 Thread（執行緒）
  • Postmaster 是主要監督程序，負責監聽連線請求（僅監聽 1 個 TCP Port）
  • 每個客戶端連線會 spawn 一個獨立的 postgres backend process
  • 透過 Semaphores 和 Shared Memory 進行通訊

背景程序

程序功能
Background Writer將 Dirty Data Blocks 寫入磁碟
WAL Writer定期將 WAL 刷新至磁碟
Checkpointer自動執行 Checkpoint
Autovacuum Launcher啟動 Autovacuum Worker
Autovacuum Workers回收 Dead Tuples 佔用的空間
Archiver封存 WAL 檔案
Logging Collector路由 Log 訊息至 syslog/eventlog/log 檔案
Logical Replication Launcher啟動邏輯複寫的 Apply Process

記憶體架構

類型元件說明
Shared Memoryshared_buffers共享緩衝池，快取磁碟資料
wal_buffersWAL 緩衝區
Process Array追蹤所有活躍程序
Per-Sessionwork_mem排序/雜湊操作記憶體
maintenance_work_memVACUUM、CREATE INDEX 等維護操作
temp_buffers暫存表快取

SQL 處理流程

Parse（語法檢查）→ Optimize（查詢計畫最佳化）→ Execute（執行）

磁碟寫入機制

階段說明
Before Commit未提交的更新存在記憶體中
After CommitWAL Buffers 寫入磁碟（WAL 檔案）
After Checkpoint修改過的資料頁從 Shared Memory 寫入資料檔案
📌 每個 Page 大小為 8KB

連線設定

參數預設值說明

記憶體設定

參數說明建議
shared_buffers共用緩衝池，快取磁碟資料（整個叢集共用）系統記憶體的 25%

temp_buffers暫存資料表的快取記憶體每個 Session 獨立
autovacuum_work_memAutovacuum worker 記憶體預設 -1（使用 maintenance_work_mem）

WAL 設定

參數預設值說明
wal_levelreplicaWAL 記錄層級（minimal / replica / logical）
wal_buffers-1（自動）WAL 緩衝區大小（約 shared_buffers 的 1/32）
min_wal_size80MB開始回收 WAL 檔案的大小
max_wal_size1GB強制 Checkpoint 的 WAL 大小

修改參數方式

方式範圍說明
編輯 postgresql.conf叢集層級需重啟或 reload
ALTER SYSTEM SET叢集層級寫入 postgresql.auto.conf
SET 指令Session 層級僅影響當前連線
ALTER DATABASE資料庫層級針對特定資料庫
ALTER USER使用者層級針對特定使用者
💡 查看參數：SHOW shared_buffers;
重新載入設定：SELECT pg_reload_conf();
修改叢集參數：ALTER SYSTEM SET work_mem = '20480';
重設參數：ALTER SYSTEM RESET work_mem;

三、安全性（Security）

pg_hba.conf（主機型存取控制）

  • 控制客戶端認證，位於叢集資料目錄
  • 規則由上到下依序處理，第一條符合的生效
  • 變更後需執行 reload
  • 格式：TYPE DATABASE USER ADDRESS METHOD
  • 查詢：SELECT * FROM pg_hba_file_rules;

認證方法

方法說明
trust不需密碼（⚠️ 不建議生產環境）
reject無條件拒絕連線
scram-sha-256✅ 建議使用的密碼驗證方式
md5MD5 密碼驗證
password明文密碼（⚠️ 不建議）
peer本地 OS 使用者名稱驗證（僅限本地連線）
ident透過 ident 伺服器取得 OS 使用者名稱（TCP/IP）
ldapLDAP 伺服器認證
radiusRADIUS 伺服器認證
certSSL 客戶端憑證認證
💡 密碼加密方式由 password_encryption 參數控制（預設：scram-sha-256）

角色與權限

  • 使用者在叢集中是全域的，不是 OS 使用者
  • postgres 是預設的超級使用者
  • CREATE USER = CREATE ROLE + LOGIN 權限
  • 使用者名稱不能以 pg_ 開頭
  • 預定義角色：pg_read_all_data、pg_write_all_data、pg_monitor、pg_signal_backend、pg_checkpoint

Row Level Security (RLS)

  • GRANT/REVOKE 只能控制到資料表層級，RLS 可限制到資料列層級
  • 啟用：ALTER TABLE accounts ENABLE ROW LEVEL SECURITY;
  • 建立策略：CREATE POLICY policy_name ON table_name USING (expression);

邏輯備份工具

選項說明

pg_restore 重要選項

選項說明
-d <dbname>指定目標資料庫

-c / --clean先 DROP 再建立物件

-t <table>僅還原指定資料表
-l顯示備份檔案的 TOC 清單

pg_basebackup（實體備份）

  • 線上二進位備份，可用於 PITR 或串流複寫
  • 常用：pg_basebackup -h localhost -D /path/pgbackup -R
  • 選項 -D：指定輸出目錄
  • 選項 -R：自動建立 standby.signal 及設定 postgresql.auto.conf
  • 驗證：pg_verifybackup /path/pgbackup

前置設定

wal_level = replica
archive_mode = on
archive_command = 'cp -i %p /home/postgres/archive/%f'
max_wal_senders = 3

PITR（Point-in-Time Recovery）

需要：完整實體備份 + WAL 封存日誌
  1. 停止資料庫伺服器
  2. 清空資料目錄
  3. 從備份複製資料檔案至資料目錄
  4. 設定 restore_command 和 recovery_target_time
  5. 建立 recovery.signal 檔案
  6. 啟動伺服器（還原完成後 recovery.signal 自動移除）

七、複寫與高可用（Replication & HA）

Physical Streaming Replication

  • 直接串流 WAL 至 Replica，wal_level = replica
  • 需設定 max_wal_senders
  • 建立 standby.signal 檔案啟動 Replica
  • primary_conninfo 指定連線至 Primary
  • 同步 vs 非同步：同步等待 Replica 確認後才 Commit；非同步不等待
  • synchronous_standby_names 啟用同步複寫
  • 非同步支援 Cascading（Replica 串流至另一個 Replica）

監控視圖

視圖位置功能
pg_stat_replicationPrimary顯示已連線 Replica 的狀態
pg_stat_wal_receiverReplica顯示 WAL Receiver 程序狀態
pg_is_in_recovery()任一端檢查是否為 Replica（回傳 true）
pg_stat_activity任一端顯示目前執行中的查詢

Logical Replication

  • wal_level = logical
  • 使用 PUBLICATION（發布端）和 SUBSCRIPTION（訂閱端）
  • 需設定 Replica Identity 才能支援 UPDATE/DELETE
  • 支援跨版本複寫

八、其他重要概念

Tablespace

  • 實體目錄，用於存放資料庫物件
  • 預設有 pg_global 和 pg_default
  • 建立：CREATE TABLESPACE ts_name LOCATION '/path';
  • default_tablespace：新物件的預設 Tablespace
  • temp_tablespaces：暫存表使用的 Tablespace

Schema

  • 邏輯容器，預設為 public
  • 搜尋順序由 search_path 控制
  • 查看：SHOW search_path;

Database Cluster

  • 由單一伺服器實例管理的資料庫集合
  • 初始化：initdb
  • 啟動：pg_ctl start
  • 停止模式：smart（等待斷線）、fast（強制斷線）、immediate（立即停止）

SERIAL vs IDENTITY

項目SERIALIDENTITY
標準PostgreSQL 特有✅ SQL 標準（建議使用）
GENERATED ALWAYS—不允許手動插入值
GENERATED BY DEFAULT—允許手動插入值

其他

  • Autocommit：DDL 語句自動 Commit
  • COPY 指令：COPY emp TO '/path/emp.csv' WITH CSV HEADER;
  • psql 用戶端：\copy tablename TO 'filename.csv' CSV
